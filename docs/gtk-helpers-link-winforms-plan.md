# Vb6ToCSharp.Gtk.UpgradeHelpers links the WinForms sources

The Gtk package keeps its own copy of the 14 WinForms helper files, six of them carrying 25 `#if GTK` blocks
around API `Gtk.Windows.Forms.Base` lacked. The copies go; the project links the WinForms files instead.

## What is actually missing

Measured, not guessed: a throwaway project compiled the 14 WinForms files plus the shared projitems (76 files)
against `Gtk.Windows.Forms.Base 1.4.2464.26267`. **One** error:

```
CS0506: 'DriveListBox.OnSelectedIndexChanged(EventArgs)': cannot override inherited member
        'ComboBox.OnSelectedIndexChanged(EventArgs)' because it is not marked virtual, abstract, or override
```

Everything else the guards work around — `SaveFileDialog.OverwritePrompt`, the `FontDialog` properties,
`Form.ActiveForm`, `CheckedListBox`, `TreeNodeCollection.Find`, `DataGridView.ColumnCount` / `CurrentCell` /
`HitTest`, `ToolStripDropDown.Show`, `ListBox.BeginUpdate` — the package has since gained. The guards are stale.

## Decisions taken

| Decision | Consequence |
|---|---|
| Make the six `OnSelected{Index,Item,Value}Changed` of `ComboBox` and `ListBox` virtual | fixes the family WinForms declares virtual, not only the member that blocks the build. The other three non-virtual `OnXxx` in the library are left alone: WinForms declares `AutoCompleteStringCollection.OnCollectionChanged` non-virtual too, and `ToolStripDropDownMenu.OnFontChanged` / `OnPaintBackground` should be `override`, which is a different bug |
| Edit the generated source **and** add a `patches/` patch | `Gtk.Windows.Forms/` is regenerated by `PrepareProjects`; without the patch the fix is lost on the next run |
| Rebuild `Gtk.Windows.Forms.Base` into the shared local feed, no nuget.org push | the linked project cannot compile until the new package is on `D:\Starb\Packages` |
| Drop the `InternalsVisibleTo` for the non-existent `Vb6ToCSharp.Gtk.UpgradeHelpers.Tests` | the WinForms test project already covers this code |

## Changes

### 1. `Net4x.GtkWindowsForms` — six event raisers become virtual

| File | Members |
|---|---|
| `Gtk.Windows.Forms/System/Windows/Forms/ComboBox.cs` | `OnSelectedIndexChanged` (310), `OnSelectedItemChanged` (319), `OnSelectedValueChanged` (328) |
| `Gtk.Windows.Forms/System/Windows/Forms/ListBox.cs` | `OnSelectedIndexChanged` (1074), `OnSelectedItemChanged` (1088), `OnSelectedValueChanged` (1097) |

`protected void OnXxx(EventArgs e)` → `protected virtual void OnXxx(EventArgs e)`. The library already declares
377 `OnXxx` virtual against 9 that are not, so this is the rule, not an exception.

Then, per [Patches.txt](../../Net4x.GtkWindowsForms/Patches.txt): commit **only these two files** (the working tree
has unrelated pending edits to `Directory.Nuget.Props` and a WebView2 `.xml`, which stay uncommitted), then
`git format-patch -o patches/ -1 HEAD -- :(exclude)*.csproj`.

Then `dotnet build Gtk.Windows.Forms/Gtk.Windows.Forms.csproj`, which packs
`Gtk.Windows.Forms.Base` into the shared feed.

### 2. `Vb6ToCSharp.Gtk.UpgradeHelpers` — no sources of its own

Delete all 14 `.cs` files (`Dialogs\`, `WinForms\Controls\`, `WinForms\Helpers\`) and link the WinForms ones:

```xml
<ItemGroup>
    <!-- the Gtk package is the WinForms package built against Gtk.Windows.Forms: same sources, same namespaces -->
    <Compile Include="..\Vb6ToCSharp.WinForms.UpgradeHelpers\**\*.cs"
             Exclude="..\Vb6ToCSharp.WinForms.UpgradeHelpers\obj\**\*.cs;..\Vb6ToCSharp.WinForms.UpgradeHelpers\bin\**\*.cs"
             Link="%(RecursiveDir)%(Filename)%(Extension)" />
</ItemGroup>
```

A glob, so a file added to the WinForms package reaches the Gtk one without another edit. `Link` keeps the folder
structure in the IDE. The `Import` of `Vb6ToCSharp.Base.UpgradeHelpers.Shared.projitems` stays — it is what the
WinForms package gets from its `ProjectReference`. `<DefineConstants>…;GTK</DefineConstants>` and the stale
`InternalsVisibleTo` go; nothing else in the repository reads `GTK`.

The project keeps its own `README.md` (packed) and its package metadata.

## Verification

| Step | How |
|---|---|
| the Gtk library still builds and tests | `dotnet build`/`dotnet test Gtk.Windows.Forms.sln` |
| the new package reaches the feed | `Gtk.Windows.Forms.Base.1.4.2464.<build>.nupkg` in `D:\Starb\Packages` |
| the linked project compiles with no conditionals | `MSBuild Vb6ToCSharp.slnx -restore`; `grep -r "#if" Vb6ToCSharp.Gtk.UpgradeHelpers` finds nothing |
| nothing else regressed | `dotnet test Vb6ToCSharp.slnx --no-build` |

## Risks

| Risk | Mitigation |
|---|---|
| the patch does not apply on the next pipeline run | produced with the repo's own recipe, from a commit containing only the two files |
| a future WinForms-only file breaks the Gtk build | the glob pulls it in, so the Gtk project fails loudly at build time rather than drifting silently |
| the Gtk package is behind on some other API the guards hid | measured: the probe found exactly one error, and the final build is the same check |
